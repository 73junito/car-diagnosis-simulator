# Support

## Repository support

Use a GitHub issue for reproducible project bugs, documentation problems, feature proposals, and development questions that are safe to discuss publicly.

A useful issue includes:

- the affected page, route, command, or component
- expected behavior
- observed behavior
- reproduction steps
- browser / Node.js / operating-system details when relevant
- logs with credentials and private data removed

## Security issues

Do **not** use a public support issue for vulnerabilities, credentials, private learner data, or exploitable details. Follow `SECURITY.md`.

## Production and account support

Repository issues are not a secure account-support channel. Do not post passwords, access tokens, billing details, student records, or other private account information.

For public site contact information, use the contact mechanisms published by the deployed application rather than inventing contact details in repository issues.

## Governance and content questions

Questions about curriculum approval, assessment eligibility, evidence rights, safety review, or content governance should reference the exact artifact or approval record involved. Approval is scoped; it should not be inferred from a different course, question bank, source, or prior review.
